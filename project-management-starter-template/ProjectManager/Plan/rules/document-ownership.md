# 文档归属与渐进式披露规则

## 功能 / 能力规格归属

每个长期能力相关的设计文档统一收纳到 `ProjectManager/Specs/<feature-slug>/`。

1. 一个能力一个子目录，命名用 kebab-case 语义名。
2. `current.md` 是该能力的当前权威状态，只写已经验收确认的长期生效行为。
3. 子目录内其他文件用 `YYYY-MM-DD-<中文可读主题>.md`，记录调研、方案、决策复盘和版本变更过程。
4. 跨能力共用规格放 `Specs/` 根目录。
5. `Specs/_index.md` 使用相对 `Specs/` 的路径。

## Current Spec 回写门槛

`current.md` 代表“现在项目实际上承诺什么”，不代表“正在尝试什么”。

1. 开发期不回写。
2. 验收确认后回写。
3. 开发期在 subplan 头部写 `Spec impact` 和待回写要点。
4. 无长期行为变化可标 `none`。
5. 需要延期回写时必须显式写 `deferred` 原因。

## 子计划 Plan 归属

子计划放在：`ProjectManager/Plan/vX.Y/subplans/YYYY-MM-DD-<代号>-<中文可读主题>.md`。

Plan 按版本聚合，Specs 按能力聚合。二者通过 Plan 头部、索引和文档标题互相指向，不要求目录镜像。

## 工具性子计划范围

工具性子计划只覆盖开工时已经存在的项目能力。新能力开工时，把所需工具能力作为该能力子计划的一部分一并做掉；工具本身可预留扩展入口，但不预先实现未来功能的具体扩展项。
